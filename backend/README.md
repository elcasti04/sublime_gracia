# Backend image storage

Product images are uploaded by the existing admin form. When all GitHub
settings below are present, the backend sends the image to the GitHub Contents
API and stores the returned public `raw.githubusercontent.com` URL in the
existing `productos.img` column. Existing absolute image URLs are preserved
when a product is edited without selecting a replacement image.

If none of the GitHub settings are present, product images continue to use the
local `uploads/productos` directory for local development. A partially
configured GitHub integration fails with an explicit error instead of silently
falling back to ephemeral storage.

Payment receipts are separate from product images and continue to use
`UPLOADS_DIR/comprobantes`, served at `/uploads/comprobantes/...`. On a
Render service without a persistent disk, those receipt files remain subject
to the platform's ephemeral filesystem behavior.

## Render environment variables

Set these on the backend web service in Render; never add the private token to
the frontend or commit it to the repository:

| Variable | Value |
| --- | --- |
| `GITHUB_TOKEN` | Fine-grained personal access token with access only to the selected repository and **Contents: Read and write** permission |
| `GITHUB_OWNER` | GitHub account or organization that owns the image repository |
| `GITHUB_REPO` | Name of the public repository used for images |
| `GITHUB_BRANCH` | Existing branch where image commits should be created |
| `GITHUB_IMAGES_DIRECTORY` | Repository directory, for example `imagenes/productos` |

Create the fine-grained token in GitHub under **Settings → Developer settings →
Personal access tokens → Fine-grained tokens**. Select only the image
repository and grant **Contents: Read and write**. The repository must be
public for the raw image URLs to be publicly accessible. Protect the token as a
secret in Render and rotate it if it is exposed.

The repository path and filenames are generated by the backend; user-provided
filenames are not used as GitHub paths. Accepted uploads are PNG, JPEG/JFIF,
GIF, WebP and AVIF images up to 5 MB. The backend checks both the declared
MIME/extension and the image file signature before sending bytes to GitHub.

## Existing images

The API continues to return the existing `img` field. Absolute URLs (including
GitHub raw URLs) remain unchanged. A legacy `/uploads/...` URL is retained
when editing a product without selecting a new image; select a replacement in
the admin form to upload it to GitHub and update that product's `img` value.
An upload failure does not change the product record. Old GitHub image files
are not deleted when replacing an image.

Images already missing from Render cannot be recovered by this change. Restore
them from a local backup or select and upload them again from the admin form.
